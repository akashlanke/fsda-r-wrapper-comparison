# Spec 025 — R wrapper strategies: evaluation matrix

> Read `CONSTITUTION.md` first. This spec compares three ways of exposing FSDA to R over the shared
> Python engine and records the evidence. It is an evaluation, not a release: no package is
> published, no CI is added.

## Contract

- **Deliverable:** `docs/r-wrapper-comparison.md` — a matrix (rows = 14 criteria, columns = A, B, C)
  with the evidence for each cell and a recommendation. Supporting code:
  - **A** (Sol 2, Qaseem): `packages/fsdabridge/` imported unchanged from `qaseem97/Rpackage` —
    one dynamic `$` facade, no per-routine code.
  - **B** (Sol 1, Giacomo): `packages/fsdabridgeGen/`, generated by `tools/codegen/gen_r.py` from a
    temporary IR file `tools/codegen/tmp_spec.json` covering 10 routines (mahalFS, Score, FSR, mcd,
    pcaFS, corrNominal, tclustIC, histFS, logfactorial, GowerIndex).
  - **C** (hybrid): A plus a `.DollarNames` method fed from a JSON routine list and
    `fsda_help(name)` returning MATLAB `help <name>`; built by `tools/r-compare/make_hybrid.R` from
    A + an overlay, as package `fsdabridgeHybrid`.
- **Done when:** every matrix cell cites a raw number or log produced by a script under
  `tools/r-compare/`; correctness (row 5) runs the `check_engine.R` cases through each package's own
  call surface at `atol 1e-9`; failures are classified per README §6 (a `MatlabExecutionError` is
  MATLAB rejecting inputs, not a bridge gap).
- **Out of scope:** generating all ~500 wrappers (only a dry run to measure size/time); publishing;
  changes to `code/fsda_engine/engine.py`; a Julia façade (row 14 is a note only).

## Design

- **Files:**
  - `packages/fsdabridge/` — A, verbatim from upstream `Rpackage@4f701d9`.
  - `tools/codegen/gen_r.py` — new R emitter over the IR (§4 of `DESIGN-codegen-parser.md`); the
    parser itself is untouched unless a gap blocks generation.
  - `tools/codegen/tmp_spec.json` — temporary hand-curated IR for the 10 routines.
  - `packages/fsdabridgeGen/` — B, generated output (regenerable; committed for review).
  - `tools/r-compare/hybrid/` + `make_hybrid.R` — C overlay and builder.
  - `tools/r-compare/*.R|*.sh` — one script per test row; logs land under `tools/r-compare/logs/`.
  - `docs/r-wrapper-comparison.md` — the matrix.
- **Signatures / calls:**
  - A/C: `fsda$Score(y, X, la = la, intercept = TRUE)`; C adds `fsda_help("Score")`.
  - B: `Score(y, X, la = NULL, intercept = NULL, ..., nargout = 1L)` — required inputs positional,
    name/value inputs as `NULL`-default formals (dropped when `NULL`), `...` forwards options the
    JSON does not list.
- **Marshalling notes:** all three call `FsdaEngine.call` through reticulate; B and C ship the same
  `engine.py`. No marshalling is changed, so correctness differences can only come from the R layer.
- **Reference oracle:** the golds and inline oracles already used by `code/fsda_engine/check_engine.R`
  (read-only).
